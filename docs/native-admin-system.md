# 原生上游账号与系统诊断

入口位于原生管理员后台的“概览与同步”和“上游与系统”。界面使用 Compose 原生表单与状态卡，不加载网页，也不以原始 JSON 作为管理界面。

## 能力

- 概览：全站与按楼栋的机器数量、空闲、使用中、故障，楼层摘要、同步时间与失败次数、账号池冷却、用户与内容计数。
- 手动同步：确认后调用现有同步入口，完成后重新读取概览；提示同步可能触发正常提醒。
- 上游账号：查看序号、备注、授权是否存在、有效期、存活检测、冷却和配置来源；支持检测存活、单账号更新、短信登录并写入指定账号、批量替换账号池。与 Web 保持相同的服务端格式和最多 20 个账号约束。
- 钉钉诊断：分别显示登录凭据是否已配置、私聊/群聊就绪状态、自动播报楼栋、回调次数与最近回调。可单独清空统计，或明确确认后同时移除群会话绑定。
- 测试消息：私聊与群聊分开确认，提示会实际发送样例；发送结果显示成功/失败。
- 上游连接：默认或指定账号诊断，展示楼层目录、设备目录、设备状态的 HTTP 状态码和耗时，以及账号池冷却摘要。
- 定时同步：读取建议间隔，不展示、复制或保存带密钥的同步地址。

## 权限与敏感信息

采用共享的 `AdminController` 与同一登录会话。界面读取 `adminSystem` 的查看/操作权限；服务端继续执行角色、范围与会话校验。概览手动同步同样要求系统操作权限。共享控制器在提交期间阻止再次提交，读取与操作结束后更新现有页面，不新建网络轮询。

token、导入文本、手机号和验证码只保存在当前表单的普通 `remember` 状态，不写入可恢复状态、配置文件或日志。授权/验证码提交结束后清空，离开表单时清空所有敏感输入；授权更新不回显已有值。后台外层启用截屏保护。

诊断渲染采用显式字段名单，排除上游地址、学校位置编号、完整请求路径、预览响应、用户的钉钉标识和带密钥同步地址。提交错误与事件信息复用统一请求层；通道发送失败时提示检查服务端日志，不直接展示上游原始错误串。

短信发送前确认，成功后依据服务端 `waitSec` 以单调时钟倒计时。服务端频率限制仍是最终依据；关闭页面不会触发发送，倒计时不发网络请求。

本次代码仅完成接入，未对生产通道发送短信或测试消息。实际权限、上游短信接口、群通道和云端定时器仍应在授权账号下验收。
