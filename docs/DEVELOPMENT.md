# 开发说明

Android 10 及以上，Kotlin + Jetpack Compose Material 3，Filament 原生 3D。所有页面由原生控件绘制；登录拉起钉钉客户端，未安装时给出提示。

## 构建

需要 JDK 17 或 21、Android SDK 36。项目包含 Gradle Wrapper 和发行包 SHA-256 校验。

```sh
./gradlew -p buildSrc test --no-configuration-cache
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --no-configuration-cache
```

本地 `local.properties` 配置 `sdk.dir`。发行包的 HTTPS 服务根地址通过私有 `WESHIRT_API_BASE_URL` 环境变量注入；应用不提供地址编辑入口，也不沿用旧版本保存的地址。无配置的公开源码用于调试和自动测试，分发前必须注入服务地址。公开源码不包含学校、正式域名、账号或凭据。

`local.properties` 使用 Java Properties 格式；Windows 路径请写为 `C:/Android/sdk` 这样的正斜杠路径，避免反斜杠被当作转义符。环境变量优先于同名本地属性。客户端 FCM 和基础 U-Push 配置见 [PUSH.md](PUSH.md)，服务端凭据和 CloudBase 原子存储见 [API.md](API.md)。

Android 仓库保留原有 `main` 分支，开发提交先进入 `dev`，通过 CI 和审核后晋升 `main`。后端仓库继续使用 `dev → master`，生产由 `master` 部署。

## 自签名分发

正式包名 `com.laoke.weshirt`；调试包名额外包含 `.debug`。钉钉须登记正式包名与实际签名指纹；推送平台登记同一发行应用，调试包需要单独配置。签名私钥始终保存在仓库之外。

发布构建读取以下本地配置或同名环境变量：

| 配置 | 用途 |
| --- | --- |
| `WESHIRT_KEYSTORE` | 私有 keystore 路径 |
| `WESHIRT_STORE_PASSWORD` | keystore 密码 |
| `WESHIRT_KEY_ALIAS` | 默认为 `weshirt` |
| `WESHIRT_KEY_PASSWORD` | 签名密码 |

```sh
./gradlew :app:assembleRelease --no-configuration-cache
```

需要保留同一签名才能覆盖升级。APK 不上传公共制品站；私有分发时同时提供版本号和 SHA-256。

仓库不附带 keystore。没有配置签名时，`assembleRelease` 只会生成未签名 APK；必须使用部署方保管的自签名证书签名后才能安装、覆盖升级和登记平台应用。正式授权及投递验收使用 `com.laoke.weshirt` 的实际分发包与签名。

## 当前接入范围

原生页面、3D、登记、排队、频道媒体、朋友代取、助手/Skills/记忆、巡检、管理员后台、本地通知与桌面小组件均在本仓库，入口见 [功能对照](native-parity.md)。频道通过已有鉴权接口取得短期票据，使用原生 OkHttp WebSocket 接收变更信号；正文始终从鉴权 HTTP 接口读取。未配置网关时退回可见页面定期刷新，后台停止页面连接。

客户端仅使用 FCM 和基础 U-Push，已有实际 SDK 回调与后端发送适配器。登记应用、云端配置及真机验收是正式投递的前提；基础 U-Push 不代表已接入设备厂商的离线通道。厂商私有灵动岛以及 iOS/TestFlight 不属于当前 Android 交付；Android 16 的标准 Live Updates 由系统决定是否展示。

## 洗衣房、登记与机器留言

3D 使用与 Web 相同的两排相对机位、编号、门口视角及主要设施，机位只展示服务端绑定的设备。没有已配置场景、没有有效机位绑定或渲染初始化失败时，直接使用 2D 看板；不在启动时弹出“找不到场景”。渲染失败后的列表提供重试入口。原生场景继续按需绘制，暂停或离开页面后释放相应渲染工作。

2D 看板将洗衣机和烘干机分组，支持分类和常用筛选。组内空闲设备优先，再根据当前状态和预计结束时间排序；疑似未取、待复核与故障设备有独立标记，不会因倒计时归零就变为空闲。默认使用列表，可切换卡片。

登记表单与 Web 使用同一含义：标准洗 30 分钟、加强洗 42 分钟、加强 40°C 50 分钟、加强 60°C 70 分钟、桶自洁 6 分钟，也可填写洗衣 1–180 分钟或烘干 10–180 分钟的整数时长。上游提供有效余时时可选择跟随设备。桶自洁程序与“洗衣前已完成自清洁”记录分别保存；公开备注、消毒液和自清洁记录会在机器详情与看板显示。提交前需要二次确认，失败时保留输入；登记只安排提醒，不控制机器。

机器留言复用 Web 的楼栋频道和机器筛选，登录后按楼栋权限查看、发布、回复和举报。昵称、楼栋、身份与置顶状态沿用服务端结果；禁言用户不能发送。翻页、账号或楼栋切换均重新核对当前范围，防止旧响应串入其他会话。

## 数据与性能

- 安装 ID 保存在本地；没有临时昵称账号，游客只读，登录后复用服务端账号。
- 令牌由 Android Keystore 加密。刷新和退出串行处理；每次请求固定服务地址，切服务后旧响应不得恢复会话。
- 写操作禁用重复点击，服务端继续校验权限和幂等键。网络失败包含状态码和事件 ID。
- 看板按住宿楼查询，前台间隔刷新；后台停止刷新、3D 和不必要的渲染。动态 JSON 请求不复用 HTTP 缓存。
- 网站与楼栋目录缓存 30 秒，收藏设置、公告偏好和公告列表缓存五分钟；账号资料与权限每次刷新重新查询，手动刷新清除元数据缓存。正式包仅携带 ARM 原生库，调试包额外支持 x86 模拟器。
- 3D 以实际 GPU 帧时间和持续压力窗口判断降级，主动限帧不计作掉帧。温度、省电、屏幕刷新率会限制性能目标；降级提示显示三秒。
- 倒计时是预计时间。到零不会把设备自动改为空闲，也不会伪造“已完成”服务器通知。
- 公告以原生 Markdown 渲染；聊天图片和视频沿用频道鉴权。附件不使用公开存储链接。
